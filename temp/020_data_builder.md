## 目標 — [方向] 2026-08-17

最終的にやりたいこと:

1. アイテム・素材の効果量、印記の強さ、敵HPなどを **共通ポイント** で表す
2. そのポイントは **PL には出さない**（ルルブ・カード面は `{品質}` と普通の文章）
3. 同じ単位でアイテムと敵を釣り合わせ、データを増やしやすくする
4. **アイテムビルダー／エネミービルダー**（のち地景）のページを作る

大量のアイテム・敵・地景・タグ・印記が必要なシステムなので、ビルダーなしでは完成しない、という認識。カードゲームのカード作成に近い。

## 意見（調査を含む）

その認識は正しい。近いのは「自由記述のTRPGアイテム表」より、**セットをスロットで埋めていく TCG** である。

### TCG が実際にやっていること

マジックのデザインは、1枚ずつ天才的に書くのではなく、先に **design skeleton** を置く（MaRo "Nuts & Bolts"：スロット番号、マナ値、クリーチャー曲線、色ごとの役割）。カードはスロットを埋める。未収録の天才カードを無限に足さない。

デジタル側（ハースストーン等）は、カード本文より先に **構造化データ** がある。コスト、攻撃、体力、`mechanics: [BATTLECRY, CHARGE]`。文章は表示用。社内の「何点相当か」はプレイヤーのカード面に出さない。公開されているのはマナコストのような **1個の支払い** だけ。

自作セット用の道具（Magic Set Editor、skeleton builder）も、自由入力より **枠＋キーワード＋役割** が先。

### このプロジェクトへの写し

| TCG | こちら |
|-----|--------|
| マナコスト（PLに見える支払い） | **想成マナ** |
| クリーチャーの攻/体 | **品質 → 単体量／敵HP** |
| キーワード（飛行など） | **印記・タグ** |
| 色パイ（何をしてよいか） | **系統の2責務**（017） |
| カード・テンプレ | **018 のパターン** |
| セット骨格（スロット） | 想定マナ帯×役（雑魚／そこそこ／強敵／ボス）、系統あたりβ本数 |
| 社内ポイント | **013 の換算（単位＝品質）**。PL非公開 |
| カードXML/JSON | `data/` の行。効果文は 019 が生成 |

いまやっている換算公式は、内部ポイントの核である。ビルダーはそれを **入力フォームにした結果** で、先に作るものではない。

### ビルダーを先に作らない理由

GUI はルールが動くと即死する。先に固めるのは:

1. 単位（品質）とマナ／HP／武器の式（013・進行中）
2. パターンに「この型は品質の何割相当か」の粗い点（018＋内部表）
3. データの列（系統、マナ、パターンID、印記、品質式）— 019 の data モード
4. そのあとビルダー（スロットを選ぶ UI）

019 の「完全DSLは作らない。テンプレエンジンは作る」と同じ階層。ビルダーはテンプレの選択器である。

### 点を細かくしすぎない

`{品質/10}` の印記ごとに小数点を付けない。帯で足りる。

| 帯（仮） | 例 |
|----------|-----|
| 主量 1.0 | 単体 HP `{品質}` |
| 主量 0.3 | `{品質/3}` 系 |
| 状態 | `{品質/10}` 印記。時間・減衰は別乗数 |
| 範囲 | **攻撃は 0.5／体**（`{品質/2}`） |
| 待機 | 1カウント一旦 **5**（想成20÷4） |

禁止・推奨（系統がやってよいこと）のほうが、点よりバランスを稼ぐ。マジックの色パイと同じ。

## 敵データの成り立ち — [一旦] 2026-08-17

GURPSなどの特徴の買い／売りを敵に使う。発火は既存（GM手札1枚 → 軽／中／重／特 → その枠。[draft/rules/combat.md](../draft/rules/combat.md)）。

### 作り方

1. **想定マナ帯** と **役**（雑魚／そこそこ／強敵／ボス）を選ぶ
2. 式から **基準HP・基準火力・自由ポイント** が一意に出る（係数は一旦）
3. 4枠は最初から **基準攻撃**。自由点を HP・火力・枠の強化／入れ替え・±特徴・耐性に割り振る
4. 自由点は **ぴったり使い切る**（余り・超過は不可）。マイナス特徴で点を増やしてから使うのは可

技を必ず足す必要はない。並／硬い／ボスでフォーマットを分けない。役が変えるのは基準の大きさと遭遇頭数。

**基準火力** は PC の **品質** と同じイメージ（2マナ帯の雑魚なら ≈20）。待機は武器表側。基準の第三変数にしない。

**基準攻撃** は PC 武器と同じ。`{火力品質/7×C}`。敵の武器品質＝基準火力。初期重量は **中量**（一旦）。間合・属性は武器データに準拠（一旦 0~1・無でも可）。強化は **全体＝基準火力を買う／枠＝入れ替え** で仮置き。

**点の単位** は品質。内部点。PLの効果文には出さない。

### 遭遇頭数（目安）

| 役 | 1遭遇 | 換算（一旦） |
|----|--------|----------------|
| 雑魚 | 3〜5 | 雑魚2 ＝ そこそこ1.5 ＝ 強敵1 |
| そこそこ | 2〜3 | 同上 |
| 強敵 | 1〜2 | 1 |
| ボス | 1（仮） | 何強敵分かは未（HP200から後で） |

与ダメは頭数でも稼ぐ。基準火力は **マナ帯の雑魚品質**。役は **HP・自由点・頭数**（一旦）。ボス火力をHPと同じ倍率にしない（品質200でPCを1撃するため）。

**エンカウントの出方**（カード数値・危険度 → 表、危険度でパラメータ変更）は探索側。ここは1体の基準だけ。

### 式 — HP基準 [一旦] 2026-08-18

見る順はこれ。数字は初期（マナ帯2）。

1. **雑魚1体**が原点。HP **20**。基準火力もそのマナ帯の雑魚品質（初期 **20**）
2. **火力は役で増やさない。** 強い役は袋と頭数と自由点。1撃の大きさは雑魚と同じ目安（割るとPCが落ちる）
3. **役の袋は10刻み。** 雑魚20／そこそこ30／強敵40／ボス200。換算「雑魚2＝そこそこ1.5＝強敵1」は頭数側の目安。個体HPは綺麗さを優先（そこそこは雑魚×1.5＝30。厳密に2/1.5を掛けると27だった）
4. **ボスは換算の外。** HP200＝雑魚×10。強敵40ならボス＝強敵5体分の袋

| 役 | HP | 基準火力（品質） | 雑魚何体分のHP | 1遭遇の総HP（頭数目安） |
|----|-----|------------------|----------------|-------------------------|
| 雑魚 | **20** | 20 | 1 | 3〜5体で 60〜100 |
| そこそこ | **30** | 20 | 1.5 | 2〜3体で 60〜90 |
| 強敵 | **40** | 20 | 2 | 1〜2体で 40〜80 |
| ボス | **200** | 20 | 10 | 1体で 200 |

旧「硬い 25」は捨ててそこそこ30。PC60＝強敵1.5体＝そこそこ2体。

頭数帯では雑魚群れの総HPの方が強敵より厚くなりうる。群れは1撃が分散、強敵は特殊で差が厚い。自由点は雑魚にも出す（0点固定は撤回）。大きさはスロット列挙のあと。

`f` はマナ帯で雑魚HP＝その帯の少し鍛えた品質、そこに上表の倍率（1 / 1.5 / 2 / 10）。手数の見方は [021](021_game_balance.md)。

書くとき一旦で足りる: 同一技を複数枠に置けるか。

### ビルダーへの手順 — [一旦] 2026-08-18

調査（021）でも、ここでも、**骨格は順方向・特徴の点は逆算**が正しい。図鑑を完成させてからビルダー、ではない。

順方向（もう置いた）:

1. 想定マナ帯×役 → 基準HP・基準火力・（のち）自由点予算
2. 4枠は基準攻撃から始まる

逆算の直前（スロット。図鑑ではない）:

3. **能力スロットを列挙する。** 名前の図鑑ではない。マジックのキーワードと同じ。語彙は **018の型と012の印記** を先に使う。敵専用能力は、既存型で書けないときだけ足す
4. 1行は「能力／雑魚に出していいか／PCが何で答えるか／アイテムにもなるか」。着ぐるみ（ぬる、こうもり）は後から乗せる

逆算（代表例）:

5. スロットから **数体** 書く。雑魚は **基本型＋1**。名前は別種族。そこそこ以上は同じ＋1の強い版でもよい
6. 「この敵がこの役で丁度よい」から、特徴1つの点を読む。018の単体1.0・範囲0.5／体は敵技にも流用。新品だけ逆算する
7. 自由点の大きさは、雑魚が買える小さな特徴の量から決める。巨大な特徴カタログは先に作らない

そのあと:

8. dataの列
9. ビルダー（役を選ぶ → 予算が出る → スロットから買う）

先に特徴カタログを全部点付けしてから敵を書く、でもない。PF2も特殊能力の点表は無く、レベル×役の表が先。GURPSの特徴点は何十年かの逆算の結果。マジックもキーワードコストは既存カードから読んだ。

まだやらない: 敵図鑑の本数を埋める。ビルダーUI。

### 出したい敵の列挙 — [議論中] 2026-08-18

**能力が先 — [一旦] 2026-08-18**

敵の＋1は、そのまま想成や歯車に載せられることが多い。第三の「敵専用カタログ」は作らない。

- 語彙の正は **018のパターン** と **012の印記**（吸血は歯車 D04「ダメージを与えた → 自分回復」が既にある）
- 敵はそれを **着ぐるみ** にする（ぬる＝色パッケージ、こうもり＝吸血）
- アイテム側は系統の2責務に載る。敵側は袋＋1
- 敵にしか見えない塊（爆弾岩＝吸収＋弱点＋スタン時爆発）は、あとで歯車の罠にもできるかだけ見る。先に敵専用ルールを増やさない

列挙は能力で書き、名前は個体が決まったとき付ける。

別系統（爆弾岩、こうもり、のち獣・ゴーレム等）はぬるのあとに置く。ぬるどうしは **作り方は共通、種族・名前は別個体**。

| 機能 | 雑魚で出してよいか | PC側の答え（系統・印記） | メモ |
|------|-------------------|--------------------------|------|
| **属性1つ（攻撃がそれ）＋同属性半減** | 可。袋は据え置き | 別属性・急所 | 色ぬる／ヒレ等のパッケージ |
| **代表印記1（毒・爆発）** | 可。刻みは小さく | 薬・解除／爆弾の誘爆 | 毒ぬる・爆ぬる |
| **小回復（ホイミ相当）** | 可。量はごく小さく | 火力・割り込み | 癒ぬる |
| **間合が長い** | 可。火力は据え置き | 遠の想成・造園 | ノビぬる。枠の間合を1段 |
| **装甲が少し** | 可。追加HPは小さく | 爆弾・属性 | カタぬる。HP袋とは別 |
| **指定属性を吸収し、スタンしたら爆発** | 群れには出さない | 別属性で倒す／距離を取って点火 | **爆弾岩** |
| **与ダメで自分回復（吸血）** | 可。量は半分 | 早く落とす・割り込み | こうもり。018 D04 |
| **HPが減るほど与ダメ上昇（窮鼠）** | 可。上昇幅は小さく | 一気に落とす／様子見のリスク | 印記 or 敵常時。狂化とは別（下記） |
| **行動不能・被ダメ通常（石化）** | 群れには慎重。nは短く | 薬②・時間・無防備に殴る | `<石化：n>` 案。拘束とは別 |
| **対象指定行動の対象ランダム（混乱）** | 可 | 単体狙い・遠ざける | `[ぬるぬる]` と同型の抽選ルール流用可 |
| **減衰なしで蓄積する被ダメ増（出血）** | 可。刻み小さく | 早く落とす・薬② | `<毒>` とは別。012 蓄積例外が要る |

## 型の点表は変数ではない — [議論中] 2026-08-17

効果文の `{}` に倍率変数を **増やさない**。変数は **`品質` のみ**（[013](013_expression.md)）。

βの数字は、規則で切ったものが少なく、多くはレシピごとの感覚。**カテゴリ表を先に完成させない。**

### 規則（2つだけ）

| | 倍率 | 式 |
|--|------|-----|
| 単体の火力・回復 | **1.0** | `{品質}` |
| 対象が無差別に複数（カウント上の全員など） | **0.5／体** | `{品質/2}` |

2体で単体と同じ総量、1体では負ける。回復も同じ。味方のみ範囲も人数税は同じ（召喚④）。

### 規則にしない（感覚・一旦）

`/3` `/4` `/5` `/7` `/10`、武器0.6、料理×2、歯車の等倍、毒の三角、目潰のn、段階15／25 は **個別の一旦**。第二量・確率・時間・常時攻撃などの事情が混ざっているので、いま同じ棚に載せない。

全体（間合無視）0.3は013の仮で、これも規則ではない。

量点にしない: 段階、変異④の指定。

カウント操作の点は別。

敵の枠入れ替えも、規則2つに当てはまる技は同じ値段。当てはまらない技は個別見積もりのまま。

次: カテゴリを増やさない。足りない規則が出たら足す。武器を「無料の毎ターン」として単体より安く見るか、は敵の基準攻撃とつながるので後で見てよい。
