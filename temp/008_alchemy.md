**近年作が本体を消費しない理由付け（整理）:**

1. **別リソースで回数制限** — CC・使用回数・MP 等。「アイテムを失う」代わりに「チャージを使う」
2. **登録 / 装備モデル** — コアクリスタル・戦術スロットに **事前装備**。無限ストック前提で **戦闘中は装備分だけ**
3. **調合報酬の永続化** — 良い調合結果を失いたくない → 本体 permanent、バランスはリソース側
4. **アクション戦闘との相性** — インベントリ micromanagement を戦闘から排除

→ ユーザーの **想成＝マナ再現（弱い）** は、ライザの **CC** に近い **第2リソース** として位置づけ可能。

## 議題 8-A: アイテムの本体論 — 3 モデル案

**目的:** 「錬金で何が生まれるか」「実体と想成の関係」を一貫した物語で説明する。

### モデル α: 二層（想型 + 実体）

```
錬金成功
  ├─ 実体 … 物質としての完成品（使用で消費・フル効果）
  └─ 想型 … 錬金師の中に刻まれる「形」（成功の副産物。消えない）
```

| 項目 | 内容 |
|------|------|
| **想成** | 想型 ＋ マナ → 不完全な再構成（弱い・一時的） |
| **実体** | 物質そのものを使う → フル効果 |
| **上限** | 想型の数 **に上限なし**（覚えたものはいつでも想成可）。制限は **マナ・アクション・弱さ** |

## 議題 11: 材料スロット方式 — [決定] 2026-07-07

**概要:** レシピごとに **材料スロット** を設け、スロット種別ごとに副作用の付き方が変わる。  
地景用SC・消耗品・（将来）装備は **同一錬金パイプライン**、レシピが成果物タイプを決める。

### レシピの構成

| 要素 | 内容 |
|------|------|
| 材料スロット | 複数。各スロットは3種のいずれか（**混在可**） |
| 規定タグ | 完成品に必ず付くタグ（**本体**）。分解時マナ算出の根拠 |
| 想成マナ | ダイスプール ＋ 想成コスト |
| 目標値 | レシピごと |
| 成果物タイプ | 消耗品 / 界標用SC /（将来）装備 等 |

### 材料スロット3種

各スロットに **素材を1つ** 投入する。

| スロット種別 | 記述例 | 投入条件 | 副作用 |
|-------------|--------|----------|--------|
| **特定素材** | `虹色の羽` | その素材のみ | **なし**（このスロット由来） |
| **カテゴリタグ** | `<草>` | 当該カテゴリを持つ素材1つ | 投入素材の **全タグ** が副作用 |
| **性質タグ** | `火` 等 | 当該タグを持つ素材1つ | **指定タグ以外** のタグが副作用 |

- シナリオ錬金 → **特定素材** スロット
- 地景SC → 霧域固有素材（特定）＋ 性質／カテゴリタグを組み合わせ

**例 — 界標用SC（概念）:**

```
スロット1: 虹色の羽（特定）           → 副作用なし
スロット2: <霧域の手がかり>（カテゴリ）→ 投入品の全タグが副作用
スロット3: 火山（性質）               → 火山以外のタグが副作用
規定タグ:  <密林地景>
成果物:    界標用スコーリオン
```

### 完成品のタグ

| 種類 | 内容 |
|------|------|
| **規定タグ** | レシピに記載。完成品の **本体** |
| **副作用タグ** | スロットルールで付与。使用時の副次効果 |

### 分解・マナ

- 分解時のマナ算出は **規定タグのみ**
- **副作用タグは分解に含めない**

### 副作用の引き継ぎ

- **デフォルト: 次の錬金に引き継がない**（完成品ごとに副作用は完結）
- 特記がある場合のみ例外（呪い・工房汚染等 — 未設計）

### 旧ルールからの変更

| 旧 | 新 |
|----|-----|
| レシピ＝必要タグ、素材完全自由 | **スロット方式** |
| 必須外タグ全部副作用 | **スロット種別** で副作用範囲が決まる |

### 未決

> 霧域で想成として使うには、**その完成品を手元に置く**必要がある。マナを払えば効果だけ呼び出せる。  
> 完成品を直接使えばマナは要らないが、消えてしまう。  
> 地を拓く **スコーリオン** だけは、工房で別に作り、霧域に据える。

### レシピ習得方式（系統内）— 議論 2026-07-14 [議論中]

**論点:** キャラクターごとにレシピ系統を固定し、系統内レシピは **最初から既知**（旧方針）とするか、Fear系のクラスレベル制のように **系統ごとにレベルを設け、レベルが上がるたびに1本ずつ習得**する形にするか。

**既存決定との関係:**

- **熟練度は廃止済み**（2026-07-09）。成長は「腕が上がる」ではなく「良い完成品を再錬金して乗り換える」ハクスラ寄りモデル
- 現時点で唯一の「キャラクターが強くなる」軸は **工房成長（携行枠拡張）**
- β入手方針（2026-07-03）は「最初から4系統・各4レシピ程度を既知」

**系統別レベル制を敷いた場合の懸念:**

| 観点 | 固定既知（旧方針） | 系統別レベル制 |
|------|--------------------|----------------|
| 強さの決定要因 | 携行している完成品の質・数 | レシピ解放数（＝レベル） |
| 新規参加者 | 携行枠が揃えば即戦力 | レベルが低いと選択肢が少なく、キャッチアップに時間がかかる |
| 役割分担 | 系統選択そのものが役割 | 系統内で「まだ覚えていない責務」ができ、役割が未完成な期間が生まれる |
| 数値管理 | 明示的なレベルなし | 系統ごとのレベルをトラッキングする必要がある |

レベル制は「誰がいつ参加しても大体同じ強さ」「錬金の頻度で追いつける」という設計テーゼと衝突しやすく、工房成長という既存の成長軸と**二重の成長軸**になり得る。

**代替案（レベルという数字を出さずに個性・段階性を出す）:**

- **案A: 携行数制限で運用の幅を絞る**　レシピは全部既知だが、探索に持ち出せる完成品には上限がある（既存の携行枠の仕組みを活用）。PLは「今回どのレシピの完成品を持っていくか」で個性を出す。
- **案B: 系統内レシピを緩やかに間引いて解放**　初期は系統内4本のうち2本のみ既知。残りは探索・素材入手・イベントで解放。工房成長のような**共有の成長イベント**に紐づければ、個人差が開きすぎない。数字としてのレベルは持たない。
- **案C: 系統固定＋プレイごとの選択で個性を出す**　覚える・覚えないの差ではなく、「今回どのレシピを主軸にするか」という選択で個性を出す。既存方針に最も近く、追加の管理コストがかからない。

**見立て:** レベル制を検討するなら、まず「工房成長」という既存の共有成長軸を置き換えるか、共存させるかを先に決める必要がある。共存させると工房成長が無意味化するか、レベルを上げる意味が薄れる（携行枠さえあれば強い）かのどちらかに転びやすい。**案B**（工房成長など共有イベントに紐づけた段階解放）が、既存方針との整合性が最も高い。
